# 2026-10-23 队友倒地检测验证

当前行为见 [娱乐功能](../../features/entertainment.md)。本记录只对应下列离线截图与合成增强，不代表未采样场景的实机验收。

## 数据与基线

- 旧样本：`tests/data/entertainment/go_down*` 共 17 张，宽 234–404 像素。
- 新样本：`tests/data/entertainment/teammate_video` 共 30 张，228×124 JPEG。来自日志中队友状态变化事件的随机录像帧；先居中裁剪到 16:9，再裁剪默认队友检测区。以人工重命名后的文件名为 GT，不使用日志中的算法判断作为 GT。
- `xx_a-b.jpg` 的 `a/b` 是上/下队友：`n` 无人、`0` 未倒地、`1/2` 倒地合并、`3` 三倒。旧图按原有文件名同样解析，并包含此前聚合测试未检查的 `2_3`。
- 修改前：17 张旧原图通过，新原图有 16/30 张至少一个槽位分类错误；既有头像/菜单误检，也有金色救援环漏检。较大旧图单次检测约 30–43ms。

## 调整

统一到宽 240 像素，在头像附近五种尺寸的 32×32 局部图上匹配纯几何环形模板。归一化相关性比较暗色凹槽、紫色整环和第一扇区，兼容低填充和金色救援环。整环区分三倒，一倒/二倒合并。放弃仅靠紫色覆盖和头像暗部累计分数的判断。

存在性以倒地环或具有固定起点、局部色差和连续长度的暖色血条判断，减少菜单和背景纹理冒充 HUD；低对比度淡出画面按无人处理。它依赖标定后的队友 HUD 布局和可见结构，极端裁剪、色彩丢失及其他未采样画面仍需补充真实标注。自身检测只抽出共用几何模板生成函数，原有分类参数与逻辑保留。

## 验证方法

每张样本共 141 个版本：原图；饱和度 0.5/0.75/1/1.25/1.5 × 对比度 0.6/1/1.4 × 亮度 0.6/1/1.4 × 原清晰度/7×7 σ2 模糊/锐化的 135 种组合；单独轻度模糊和锐化；0.8/1.5/3 倍分辨率。共 6,627 次完整双槽位状态检查，逐项检查存在性、倒地和三倒。

```bash
uv run pytest tests/plugins/test_entertainment_detector.py tests/plugins/test_self_down_detector.py -q
uv run python benchmark/benchmark_teammates.py --repeats 10 --output .tmp/teammate-benchmark.json
```

性能测试在单独运行时测量 `detect_rgb` 完整调用，包括归一化和两个槽位，排除解码、增强和断言。每个版本重复 10 次，共 66,270 次；记录中位数、P95、最大值以及超过 20ms 的次数。默认 pytest 不使用依赖机器负载的硬时间断言。
