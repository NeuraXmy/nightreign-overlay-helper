# 地图识别测试说明

本项目的地图识别测试覆盖地图插件状态机、特殊地形识别、POI CNN 和地图数据绘制。测试样本存放在 [`tests/data/map_detect/`](../../../tests/data/map_detect)，由 Git 跟踪；本页记录测试与历史压力评测；当前功能说明见[地图信息](../../features/map/README.md)。

## 全图检测鲁棒性评测

运行 [`benchmark/benchmark_full_map.py`](../../../benchmark/benchmark_full_map.py)：

```bash
.venv/bin/python benchmark/benchmark_full_map.py
# 需要任一误判即返回失败状态时：
.venv/bin/python benchmark/benchmark_full_map.py --fail-on-error
```

脚本默认排除已自带增强的 `12.jpg`、`1137_2.jpg`、`207_hide.jpg`，使用其余 12 张 JPEG，直接调用生产代码 `MapDetector._match_full_map`，使用默认阈值 `error <= 20` 判定全图。不调整 RGB 输入、算法或阈值。默认输出 `.tmp/full_map_benchmark.json`，可通过 `--captures` 和 `--output` 指定输入目录和报告文件。报告记录排除列表及原因，并包含每个样本的预期、预测、误差、每图与每种变换的统计、源图片 SHA-256、配置和依赖版本；误差为无穷大时用 JSON `null` 表示。

每张图产生 58 个测试样本，共 696 个，所有变换均在内存中完成，不覆盖原图，也不经额外 JPEG 压缩：

- 原图 1 个，预期为全图。
- 增强 18 个，预期为全图：饱和度 0.1、0.3、2、3 倍；亮度 0.35、0.6、1.5、2 倍；对比度 0.35、0.6、1.8、2.5 倍；锐度 1.8、3 倍；高斯模糊半径 0.5、1 像素；另加两组按饱和度→对比度→亮度顺序组合的增强 `(0.3, 0.6, 0.6)`、`(2, 1.8, 1.5)`。除这两组外，各增强独立作用于原图。
- 半透明 24 个，预期为非全图：不透明度 10%、25%、40%、49%，分别叠放在黑、灰、白、红、绿、蓝六种纯色背景上。使用 `Image.blend(background, image, alpha)` 在编码后的 RGB 空间混合。
- 裁剪放大 15 个，预期为非全图：保留原图宽、高各 50%、75%、90%，取中心及四角五个位置，使用 Lanczos 缩放回原尺寸。因此保留面积分别约为 25%、56.25%、81%。

### 判定机制与限制

生产实现仍使用左下角圆形图标作为全图锚点，并返回半径误差平方，保持原有全图阈值设置的含义。优化包含以下步骤：

1. 将整图缩小到 160 × 160，计算各通道第 1 百分位的暗部值。各通道最低暗部值高于 96，或通道暗部差超过 56 时拒绝，限制明显抬高黑位或强烈偏色的纯色叠加背景。这是经验性的亮度、偏色门控，不是固定图标配色匹配。
2. 截取左下角约 22% × 22% 区域，双线性缩放到 100 × 100；按实际 RGB 输入转灰度，替代原先的 BGR 转灰度。
3. 原始灰度极差不足 48 时拒绝，避免把微弱残影放大；其余样本归一化到 0–255 后进行霍夫圆检测，提高暗图与低对比度图的稳定性。
4. 候选圆心需处于检测区域中心横、纵各 ±8 像素内，减少局部放大后偏移圆的误接受。半径仍与 42.5 像素比较，误差不超过配置阈值才接受。检查所有返回的候选圆，成功后提前结束。
5. 首轮未通过时，以 3 × 3、sigma=0.4 的轻微高斯平滑重试，缓解锐化边缘干扰；位置、半径、原始对比度及整图暗部门控不放宽。

这些门限在当前截图及增强样本上验证有效，但仍需更多亮度、HDR、色彩滤镜和实机淡入样本验证，不能推断为所有场景都可靠。归一化也无法解决语义相同像素的歧义：“大幅降低亮度或对比度后仍接受”和“低不透明度叠加纯色背景时总是拒绝”存在输入重叠。例如亮度降到 40% 与不透明度 40% 叠加黑底具有相同的像素计算公式。剩余半透明误接受说明单帧检测不能保证等待淡入结束；如需可靠判断淡入完成，应结合连续帧或额外的显示状态依据。

## 地图渐变稳定性回归

`TRUE` 状态仅在完整地图持续通过检查、主体画面稳定至少 0.6 秒且至少有 3 张有效截图时放行地形识别。默认 250 ms 采样间隔下，稳定确认通常需要 4 张截图、跨度 0.75 秒。使用原始截图而非 HDR 归一化图判断亮度变化；比较相邻图与窗口起始图，避免慢速累计渐变被当作稳定。

[`test_map_stability.py`](../../../tests/plugins/map_detect/test_map_stability.py) 覆盖开启和关闭渐变、低速累计变化、局部动态标记、重复或倒退的采集时间、采样断档和全图失败后的历史清除。插件测试同时覆盖采集时间跨任务传递、后台回调延迟、HDR 归一化掩盖渐变及识别上下文切换。

真实时序样本位于 [`tests/data/map_detect/transitions/`](../../../tests/data/map_detect/transitions/README.md)。测试遍历每一帧作为重新识别起点，并以 1/30、0.05、0.1、0.25、0.5、1、2 秒采样，要求所有放行结果位于独立标注的完全开启窗口内；常规采样间隔还要求存在成功放行，避免全部拒识造成虚假通过。紧凑样本保存预处理图像和录制时的全图结果，不依赖未跟踪的原视频。

运行稳定性回归：

```bash
python -m pytest tests/plugins/map_detect/test_map_stability.py \
  tests/plugins/map_detect/test_map_detect.py -q
```

标注仅用于验收，不参与检测。此样本验证渐变门控，不验证 POI 或地图 ID 准确率，也不能替代更多实机视频，尤其是不同亮度、HDR 和动态地图内容下的验证。

## 特殊地形样本

样本来自 `sandbox/old_test_data/test_map_image`，目前共 15 张图片。PNG 样本已转换为 RGB JPEG（quality=95、subsampling=0），原有 JPEG 保持原文件内容。此前错误命名的 `12_2.jpg` 已更正为 `1137_2.jpg`。2026-10-15 经人工确认，`7.jpg` 更正为 `16.jpg`，`1180.jpg` 更正为 `1187.jpg`。

文件名按 `_` 分割后的第一段记录 ground truth 地图模式 ID：

- `1137.jpg` 表示只接受地图模式 `1137`。
- `1126-1176_hide.jpg` 表示识别出 `1126` 或 `1176` 都算正确。
- 文件名包含 `hide` 表示夜王信息隐藏；本组回归测试只验证特殊地形，因此不依赖夜王识别。

文件名中的数字是地图模式 ID，不是特殊地形 ID。测试会从程序加载的地图模式数据中取得对应的 `earth_shifting`，再与检测结果比较。

## 测试脚本

### `tests/plugins/map_detect/test_map_terrain.py`

这是特殊地形算法的样本回归测试：

1. 逐张读取 `tests/data/map_detect/*.jpg`。
2. 根据文件名解析一个或多个地图模式 ID。
3. 通过 `MapDetector.info.patterns` 获取这些模式对应的特殊地形集合。
4. 调用完整的 `MapDetector.detect()` 流程，而不是只调用内部匹配函数。
5. 默认使用 NCC 算法，检查返回的特殊地形属于 ground truth，并检查分数通过 NCC 默认阈值。
6. 额外验证 NCC 和模板匹配的阈值互不影响，以及纯色无结构图像会被 NCC 拒绝。

NCC 返回原始归一化相关系数，范围是 `[-1, 1]`，越高越匹配；当前默认阈值为 `0.4`。模板匹配继续返回原有误差分数，越低越匹配，默认误差阈值为 `50`。两种算法的配置项和阈值分开保存。

运行单项测试：

```bash
QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest tests/plugins/map_detect/test_map_terrain.py -q
```

### `tests/plugins/map_detect/test_map_nightlord.py`

这是当前夜王模板匹配算法的准确率测试，复用上述 15 张地图截图，直接调用生产代码的 `MapDetector._match_nightlord()`：

1. 使用 PIL 将截图读为 RGB 数组，保留完整地图裁剪；由生产函数完成缩放、左下角夜王区域裁剪和多尺度模板匹配。
2. 普通样本从文件名解析地图模式 ID，通过 `MapDetector.info.patterns` 取得对应的 `nightlord` 作为期望值；多个模式对应的夜王均可接受。
3. **文件名含独立 `hide` 标记的样本只接受 `None`，即 `icons/nightlord/unk.png` 对应的隐藏夜王，不使用地图模式的真实夜王作为期望值。**
4. 不运行地图候选匹配或 POI 推断，不使用地图 ID 修正识别结果。算法返回的夜王 ID 直接与期望值比较，分数必须为有限数。
5. 输出每张截图的期望值、实际值和匹配误差分数，以及总体、可见夜王和隐藏夜王三组准确率。每张截图独立断言，误识别会导致 pytest 失败，不跳过或标记为预期失败。

运行命令（即使不加 `-s`，也会输出准确率和逐样本报告）：

```bash
QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest tests/plugins/map_detect/test_map_nightlord.py -q
```

2026-10-15 回归测试结果：

| 分组 | 正确 / 样本数 | 准确率 |
|------|---------------|--------|
| 总体 | 15 / 15 | 100.00% |
| 可见夜王 | 12 / 12 | 100.00% |
| 隐藏夜王（unk.png） | 3 / 3 | 100.00% |

隐藏样本的逐张结果（误差分数越低越匹配）：

| 样本 | 期望值 | 实际值 | 匹配分数 |
|------|--------|--------|----------|
| `1126-1176_hide.jpg` | `None`（unk.png） | `None`（unk.png） | 0.091471 |
| `207_hide.jpg` | `None`（unk.png） | `None`（unk.png） | 0.039759 |
| `251_hide.jpg` | `None`（unk.png） | `None`（unk.png） | 0.107766 |

当前函数将普通和深夜夜王图标映射到相同的数字 ID，因此该测试衡量夜王 ID 和隐藏状态的准确率，不区分普通与深夜图标。该函数没有分数拒识阈值，测试不会额外引入阈值。以上结果仅代表这组固定截图，不代表所有实机截图的准确率或所有夜王类别均已覆盖。

### `tests/plugins/map_detect/test_map_detect.py`

验证地图插件的常规行为，包括：

## 推荐验证顺序

修改特殊地形算法或阈值时，先运行样本回归，再运行地图插件测试和 POI CNN 测试：

```bash
QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest tests/plugins/map_detect/test_map_terrain.py tests/plugins/map_detect/test_map_detect.py -q
QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest tests/plugins/map_detect/test_poi_cnn.py -q
```

提交前还应运行：

```bash
.venv/bin/ruff check src tests
.venv/bin/ruff format --check src tests
git diff --check
```

当前样本覆盖六类特殊地形，并要求默认 NCC 在这 15 张图片上全部正确；这属于固定样本回归指标，不代表对所有实机截图的准确率保证。新增截图时，应同时将图片放入 `tests/data/map_detect/`，按照上述命名规则标注，并更新本文件的样本数量或特殊情况说明。

## POI CNN 与模板算法对比

POI 识别默认使用 CNN，可在设置中切换模板算法。部署逻辑、14 张验收截图的回归测试和逐图对比结果见 [POI CNN](../../features/map/poi-cnn.md)，训练与导出说明见 [`tools/poi_cnn/README.md`](../../../tools/poi_cnn/README.md)。

全部 15 张截图均输出结果；经用户确认，难例 `207_hide.jpg` 仅排除 POI 地图 ID 与误差的验收统计，不从样本目录删除，也不影响地形/夜王测试。CNN 验收地图 ID 为 14/14，11/14 张 POI 总误差 ≤10；包含该难例时全样本正确率为 14/15。
