# 异常量表背景误检与耗时验证（2026-10-23）

本记录对应基线 `4807d4e` 上的异常量表检测修改。当前行为见[异常量表计时](../../features/debuff-timer.md)，样本说明见[回归样本](../../../tests/data/debuff/README.md)。

## 问题与修改

按默认区域裁剪新提供的 `sandbox/debuff/0.png` 至 `9.png`，基线将其中 0、1、4、6、7、8 共 6 张无量表原图误判为有量表。明暗渐变与图标灰度轮廓相关，场景纹理又能通过原有横条检查。

增加高通细节验证：模板和候选减去 σ=2 的高斯平滑结果，内裁 2 像素后比较局部符号纹理，阈值为 0.70。模板预先缓存，候选只有通过原灰度与内部匹配后才做高通验证。原来的五尺度、图标与量表联合判断保持。组合增强还发现旧阳性 `6_2.png` 在低亮度、低对比度与模糊同时存在时，横条的最低灰度差阈值过高；将最低阈值从 1.0 调整到 0.5，以保留弱横条信号。

## 样本与准确率

- 原有 12 张样本与新增 10 张反例均保留，共 8 张阳性、14 张阴性。新样本仅无损裁剪，未用于生成新图标模板。
- 每张图验证原来的 17 种原图／单项增强，以及亮度、对比度、饱和度和清晰度的 81 种组合。22 张共 2156 次识别全部正确，其中新反例为 980 次。
- 相关检测与插件测试共 73 项通过，包括各量表行单独存在、仅有图标、仅有横条和纯色反例。

这些是固定截图及合成增强结果，未进行新增真实对局、动态录像或 HDR 验收。

默认全项目回归运行 `pytest tests -m "not benchmark"`（设置 `QT_QPA_PLATFORM=offscreen`，使用仓库内临时目录），结果为 1531 项通过、1 项跳过、3 个子测试通过，耗时 143.91 秒；9 条警告来自已有血条拒识率告警。Ruff 检查、格式检查与 `git diff --check` 均通过。

## 性能

在本地 Windows、Python 3.13.16、OpenCV 5.0.0、OpenCV 默认 24 线程设置下运行：

```powershell
uv run python benchmark/benchmark_debuff.py
```

共 2178 次调用，包括 2156 次原图／增强识别和 22 次新建检测器后的首次检测。没有识别错误，也没有超过 20 ms 的调用。

| 指标 | 本次结果 |
| --- | --- |
| 中位数 | 8.07 ms |
| P95 | 9.48 ms |
| 最大值 | 15.95 ms |

计时仅包含生产 `detect()` 调用（含缩放、灰度转换、模板匹配与量表验证），不包含文件解码、增强图生成或激活时的模板加载。未修改 OpenCV 全局线程配置。完整逐次结果写入 `.tmp/debuff-benchmark.json`；该文件为本地复测产物。性能受硬件与系统调度影响，以上为本次测量结果。
