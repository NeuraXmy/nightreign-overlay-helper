# 2026-10-23 自身倒地检测验证

当前行为见 [娱乐功能](../../features/entertainment.md)。本记录对应离线真实截图和合成增强，不代表所有游戏场景的实机验收。

## 数据与基线

- 旧数据：`tests/data/entertainment/self_down` 的 4 张真实倒地图和两张背景图。沿用旧测试，按每张倒地图尺寸从对应背景中固定抽取 10 个裁剪，共 40 个背景样本。
- 新数据：`tests/data/entertainment/self_down_video` 的 20 张 75×76 JPEG，来自随机选择的 `Self status changed` 日志事件，先居中裁剪到 16:9，再裁剪默认自身检测区域，保留原始 JPEG 字节。
- 人工标注文件名 `xx_x.jpg`：`0` 非倒地，`1/2/3` 合并为倒地。共 9 张倒地和 11 张非倒地。日志只定位帧，不作为 GT。
- 修改前新原图有 1/20 张错误：`11_0.jpg` 的蓝白色特效误触发。原图及增强/缩放共 2,820 个版本中有 166 次错误，其中 99 次来自该背景，67 次为 `01_1.jpg` 金色救援环漏检。

## 调整

保留原有暗色凹槽、紫色整环、第一扇区和带掩码的连续填充检测，新增圆环边界确认：在固定 32×32 灰度图上计算 Sobel 梯度，对邻近圆心的径向投影能量除以边界总梯度能量。圆环边缘朝向共同圆心，直线或条状特效缺少这种一致性；能量比对线性亮度/对比度变化不敏感，并接受明暗两种边界。几何向量预先生成，避免运行时逐像素或逐半径搜索。

边界一致性不足时直接拒绝，防止单个局部填充模板绕过整体结构检查。金色救援环的凹槽会被重新着色，仅在圆形边界很明确时放宽暗色凹槽匹配。队友检测参数和播放状态机保持原有逻辑。

## 验证方法

64 个样本（4 旧倒地图、40 固定背景裁剪、20 新图），每张 141 个版本，共 9,024 次判断：

- 原图。
- 饱和度 0.5/0.75/1/1.25/1.5 × 对比度 0.6/1/1.4 × 亮度 0.6/1/1.4 × 原清晰度/7×7 σ2 模糊/锐化，共 135 种组合。
- 单独轻度模糊、轻度锐化，以及 0.8/1.5/3 倍分辨率。

原有 4×43=172 次倒地图增强（含 48–230 像素尺寸、±5 像素标定偏移）及固定背景检查完整保留。连续进度仍从真实三倒图仅重绘填充，保留环外、分隔线和外缘，共 727 个进度点，每点 7 个版本，合计 5,089 次。它们是合成进度，不是真实连续录像。

```bash
uv run pytest tests/plugins/test_self_down_detector.py tests/plugins/test_entertainment_detector.py tests/plugins/test_entertainment_plugin.py tests/plugins/test_entertainment_state.py -q
uv run python benchmark/benchmark_self_down.py --repeats 10 --output .tmp/self-down-benchmark.json
```

性能测试独立运行，计时包含 `is_down` 的归一化、梯度确认和全部分类逻辑，排除图片解码、增强生成和断言。9,024 个组合版本、172 个原有增强和 5,089 个连续进度版本共 14,285 个输入，每个重复 10 次，合计 142,850 次检测。默认 pytest 不对依赖机器负载的时间使用硬断言。
