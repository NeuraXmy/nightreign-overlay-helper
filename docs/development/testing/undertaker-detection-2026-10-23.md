# 送葬者额外绝招误触发验证（2026-10-23）

本记录对应基线 `aa8998f` 上的送葬者检测修改。当前功能见[绝招倒计时](../../features/timers.md#art_timer绝招倒计时)，截图来源与裁剪坐标见[样本说明](../../../tests/data/undertaker_art/README.md)。

## 问题与修改

使用生产默认绝招区域裁剪 `sandbox/undertaker/` 的三张完整截图，原算法的粉色占比分别为 95.5%、90.1%、87.3%，均超过默认 80% 阈值并误触发。样本分别包含偏红背景及受场景染色的未激活图标。

原 OpenCV HSV 色调上限为 175，覆盖到接近红色的色相；改为 150，使统计范围限于紫色至品红色（H=135–150）。饱和度、亮度下限及可配置的粉色占比阈值保持原含义。继续先缩小到 32×32，再执行颜色转换与像素计数，无需模板加载或增加结构匹配开销。

## 自动验证

1 张 active、9 张 inactive，每张保留原有 55 项原图／颜色／几何检查，另运行饱和度、对比度、亮度与清晰度的全部 135 种组合，合计 1900 项输入检查全部正确。检测器及插件相关测试 35 项通过，其中 6 项为三张新反例的 SDR／合成 HDR 截图流程检查，确认不触发 active、倒计时或音频状态。

这些结论限于已有截图与合成增强，未进行新增真实对局、动态录像或真实 HDR 验收。

默认全项目回归设置 `QT_QPA_PLATFORM=offscreen`，运行 `pytest tests -m "not benchmark"`，结果为 1541 项通过、1 项跳过、3 个子测试通过，耗时 159.64 秒；9 条警告来自已有血条拒识率告警。Ruff 检查、全量格式检查与 `git diff --check` 均通过。

## 性能

本地 Windows、Python 3.13.16、OpenCV 5.0.0 下执行：

```powershell
uv run python benchmark/benchmark_undertaker.py
```

每项输入重复 10 次，共 19000 次检测，全部正确，没有超过 20 ms 的调用。中位数 0.031 ms，P95 为 0.051 ms，最大值 0.835 ms（向上取整）。计时包含缩放、HSV 转换及颜色占比判断，不包含磁盘解码或增强图生成；未修改 OpenCV 全局线程配置。逐次结果写入 `.tmp/undertaker-benchmark.json`。耗时受运行机器和系统调度影响，以上为本次测量结果。
