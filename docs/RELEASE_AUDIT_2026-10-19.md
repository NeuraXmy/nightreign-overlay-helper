- **现象**：测试要求正文包含 `不读取/写入`，当前正文是 `不读写任何游戏进程内存`。完整测试和单独重跑均在第 64 行失败。

## P2：功能、容错、资源及验证缺口

### A02 发布构建没有可追溯的 Python 依赖锁

- **位置**：[.gitignore](../.gitignore#L13)、[build.bat](../build.bat)、[pyproject.toml](../pyproject.toml)。
- **证据**：`uv.lock` 被 `.gitignore` 忽略，`git ls-files --error-unmatch uv.lock` 确认它未被跟踪；本地存在该文件不代表干净检出或 CI 会获得它。`build.bat` 使用 `uv sync --python 3.13 --group build`，没有 `--locked`。
- **影响**：许多依赖只有最低版本约束。相同提交在不同日期或环境可能解析到不同版本；本次验证的组合未必就是以后 tag 构建的组合。这里确认的是可复现性缺口，没有证明某个新依赖版本已经导致故障。
- **建议**：将发布用锁文件纳入版本管理，在发布流程使用 `uv sync --locked`；更新依赖时通过独立变更和测试。CI 缓存键同时纳入锁文件。原生 NuGet 已使用锁文件和 `--locked-mode`，可沿用同类约束。

### A03 CI 只构建和检查文件存在，未阻止测试失败的版本产出

- **位置**：[build-windows.yml](../.github/workflows/build-windows.yml)、[build.bat](../build.bat)。
- **证据**：工作流没有 pytest、Ruff 或导入/模型加载的冒烟步骤；只在打包后检查少量路径存在。现有 A01 不会使这条构建流程失败。
- **影响**：可以产出一个没有通过项目验收的 ZIP。存在性检查也无法发现损坏模型、动态导入遗漏或资源实际不可加载。当前清单包含 POI 模型，未显式检查生产 HP 的 `material_v1.onnx`、`cap_v1.onnx`。这不等于已证明打包遗漏了它们；spec 会收集包数据。
- **建议**：在打包前运行测试和静态门禁；把完整识别回归放到适当的 CI 层级。增加无需游戏的资源/模型加载冒烟检查，覆盖两类 HP 模型和插件发现。将分发 EXE 的真实启动验证作为独立发布验收。

### A04 `RangeOption` 对 `.inf` / `.nan` 的容错不完整

- **位置**：[config.py](../src/nightreign_overlay/core/config.py#L88)。
- **复现**：整数 `RangeOption` 对 `float('inf')` 调用 `round()` 抛 `OverflowError`，`ConfigGroup.__init__()` 只捕获 `ValueError`；浮点 `RangeOption` 接受并返回 `NaN`。这两种值都可以出现在合法 YAML 中。
- **影响**：例如 `plugins.capture.interval_ms: .inf` 会令截图插件加载失败，强依赖功能随之无法激活；浮点 NaN 可能进入识别阈值或 UI。插件管理器会隔离一般加载异常，因此不能把它描述为必然使整个进程崩溃。导入入口虽拒绝非有限数值，启动时直接读取 `settings.yaml` 不走同一验证。
- **建议**：在数值规范化入口检查有限性，并将非法数值统一转换为可回退的验证错误。覆盖直接读取、导入及运行时设置三条入口。

### A05 配置备份与保存的 I/O 失败没有完整兜底

- **位置**：[config.py](../src/nightreign_overlay/core/config.py#L332)。
- **复现**：损坏 YAML 进入 `_load()` 的异常处理后，模拟 `os.replace()` 因权限失败，异常直接逃出构造函数。另一个探针让保存目标的父路径变成普通文件，`flush()` 的 `mkdir()` 在 `try` 外抛出异常。
- **影响**：损坏配置同时无法重命名时启动无法继续；运行中目录不可写、被替换或被外部删除后，保存异常可到达 Qt 回调/退出清理。`flush()` 失败后的临时文件删除也没有单独保护。没有验证这些异常必然造成进程 abort。
- **建议**：将目录创建、备份、临时文件清理纳入完整异常处理；备份失败时保留原文件并明确降级，保存失败保留 dirty 状态并给出可见提示。不要仅记录“已移动”后再执行可能失败的移动操作。

### A06 区域配置校验不满足实际 Qt 使用约束

- **位置**：[region/config.py](../src/nightreign_overlay/plugins/region/config.py#L10)、[region/plugin.py](../src/nightreign_overlay/plugins/region/plugin.py)、[region/api.py](../src/nightreign_overlay/plugins/region/api.py)。
- **复现**：`[0, 0, 2**40, 20]` 能通过 `RegionConfig` 和完整配置导入校验，随后 `QRect(*value)` 抛 `OverflowError`。零宽高和负宽高也能通过配置校验，尽管 `save_region()` 明确禁止它们。
- **影响**：成功导入并重启后，检测、状态显示或悬停预览才发现区域不可用。正常 UI 标定生成的值通常没有此问题，触发入口是外部配置或手动编辑。
- **建议**：统一校验 Qt 整数范围、坐标加尺寸的范围及正尺寸；保留负坐标副屏支持。无效区域应回退为未标定，而不是在读取服务时抛出异常。

### A07 单实例监听失败仍允许启动

- **位置**：[single_instance.py](../src/nightreign_overlay/core/single_instance.py#L26)。
- **复现**：模拟连接已有实例失败且 `QLocalServer.listen()` 返回 False，`acquire()` 仍返回 True。
- **影响**：监听权限、地址冲突或竞态条件下，进程会认为自己已获得单实例资格；后续实例可能也启动，导致共享配置、日志、全局输入及 ETW 管理出现竞争。正常单实例路径没有证明存在问题，本次没有实测并发双启动。
- **建议**：监听失败不能返回“已获得主实例”；区分陈旧地址、已有实例及不可恢复错误，必要时重试激活已有实例或明确退出。补充失败路径和并发启动测试。

### A08 插件加载异常会遗留已经注册的资源

- **位置**：[manager.py](../src/nightreign_overlay/plugin/manager.py#L120)、[context.py](../src/nightreign_overlay/plugin/context.py)。
- **复现**：构造一个在 `on_load()` 中注册服务、订阅事件后抛异常的插件。`load_all()` 将 `record.plugin` 置空，但服务和事件订阅仍存在。
- **影响**：已失败插件的回调仍可被调用，依赖方可能拿到半初始化服务；注册内容还可能持有失败插件，使其无法释放。`on_load()` 注册服务是本项目输入/音频插件实际采用的设计，不是无效用法。
- **建议**：捕获加载异常时对已创建的 context 执行清理，并保证部分构造失败也能安全释放。测试应覆盖服务、订阅和 cleanup 三类资源，而不仅是激活失败。

### A09 加载失败后界面启用操作无法重试初始化

- **位置**：[manager.py](../src/nightreign_overlay/plugin/manager.py#L240)。
- **复现**：`on_load()` 抛异常后 `record.plugin is None`；关闭再启用插件会调用 `_activate()`，该方法因没有插件对象直接返回，既不重新构造也不重新调用 `on_load()`。探针确认启用后仍无法激活。
- **影响**：即便资源或外部条件已修复，用户通过开关仍不能恢复。关闭操作还会把 FAILED 改为 INACTIVE，弱化失败提示；普通激活失败和加载失败实际拥有不同恢复能力。
- **建议**：为加载失败提供重建 context/插件的重试路径；或者在 UI 明确标注必须重启，并避免给出看似可恢复的开关状态。先处理 A08 的残留资源，防止重试重复注册。

### A10 输入初始化失败时清理注册过晚

- **位置**：[input/plugin.py](../src/nightreign_overlay/plugins/input/plugin.py#L118)。
- **静态证据**：`on_activate()` 先执行 `_start_keyboard_listener()`，成功返回后才注册 `_stop_listeners`。内部依次启动键盘、鼠标监听，再初始化 pygame；任何后续步骤抛异常，都可能使此前资源已启动但 cleanup 尚未登记。
- **影响**：插件状态变为失败后仍可能留下物理监听器或 pygame 状态。另一个相关恢复缺口是 `HotkeyApi` 只在 `on_load()` 提供，激活失败后的 `ctx.release()` 会移除它，`on_activate()` 重试并不会重新提供。没有启动真实监听器来故意触发系统故障。
- **建议**：在开始初始化前登记幂等清理，或按每个资源成功创建立即登记；让失败后的再次激活重新建立设置服务，参考音频插件的处理方式。使用 fake 初始化失败测试即可验证。

### A11 调试图片仅限制落盘数量，没有限制内存中的等待队列

- **位置**：[debug.py](../src/nightreign_overlay/core/debug.py#L54)。
- **复现**：阻塞唯一写入 worker，连续提交 65 次、每次 `keep=1`；第一个任务运行时仍有 **64 个任务**在队列中。每次提交都先复制图片，`keep` 只在写入后修剪文件。
- **影响**：慢磁盘或大量地图诊断请求会积压图片内存；退出时 `shutdown(wait=True, cancel_futures=False)` 又在调用线程等待全部写完。常见定时识别有 cooldown，会降低触发概率，但地图部分结果和标定没有统一队列上限。
- **建议**：限制总排队任务数或图片字节数；同结果名采用覆盖旧待写任务等策略；关闭时使用明确的取消/完成策略，避免无界积压。`save()` 与 `close()` 之间也应原子协调提交，避免关闭竞态中的提交异常。

### A12 绝招设置重置后，在途回调仍能启动旧识别计时

- **位置**：[art_timer/plugin.py](../src/nightreign_overlay/plugins/art_timer/plugin.py#L133)、[reset_settings](../src/nightreign_overlay/plugins/art_timer/plugin.py#L266)。
- **复现**：保存当前 `_detect_generation`，调用 `reset_settings()`，再用该 generation 交付先前帧；fake detector 返回 duchess，插件仍接受结果并设置 `_art_type`、启动计时。
- **原因**：重置没有增加 `_detect_generation` 或停止延迟检测定时器，回调也不检查当前区域是否仍等于请求时区域。其他相关插件已采用 generation 作废旧任务。
- **影响**：用户重置并清除区域后，旧截图仍可能启动一次倒计时/音频通知。
- **建议**：重置时停止延迟任务、使在途请求过期；回调交付前校验区域。补充“请求→重置→旧回调”顺序的回归测试。

### A13 手柄方向键直接换向会保留旧方向

- **位置**：[input/plugin.py](../src/nightreign_overlay/plugins/input/plugin.py#L265)。
- **复现**：给同一手柄输入 hat `(1, 0)`，然后直接输入 `(0, 1)`，按下集合变成 `dpad_right` 和 `dpad_up`，而不是只有 `dpad_up`。
- **原因**：收到有效新方向只 `_press()` 新键；只有中立或斜方向才统一释放旧方向。
- **影响**：未经过中立事件的方向切换可能误触组合键，录制出实际未同时按下的方向，或影响后续快捷键匹配。该复现使用合成 SDL 事件，没有证明所有手柄都会产生这种事件序列。
- **建议**：按每次 hat 的完整当前状态同步四个方向，先释放不再成立的方向，再按下新方向。补充直接换向、斜向和回中测试。

### A14 无托盘环境下主窗口仍只能隐藏，无法正常通过关闭按钮退出

- **位置**：[app.py](../src/nightreign_overlay/app.py#L87)、[main_window.py](../src/nightreign_overlay/ui/main_window.py#L127)。
- **静态证据**：启动时检测托盘不可用会令 `tray=None`，并正确强制显示主窗口；但 `closeEvent()` 始终忽略关闭并隐藏，没有对应降级分支。
- **影响**：无托盘时关闭按钮会让应用继续运行且失去托盘恢复入口；若又没有可交互悬浮窗，恢复依赖再次启动触发单实例激活等替代操作。源码支持的开发平台和异常桌面环境均可能涉及。
- **建议**：将托盘可用性传递给主窗口；不可用时关闭应退出或保留可见窗口并说明原因。补充 `tray=None` 的生命周期测试。
- **评论**：该问题无需修复

### A15 测试数据目录缓存没有随 fixture 清理

- **位置**：[paths.py](../src/nightreign_overlay/core/paths.py#L29)、[conftest.py](../tests/conftest.py#L29)。
- **复现**：第一次调用 `user_data_dir()` 后切换 `NROH_DATA_DIR`，函数仍返回之前的目录，因为使用无参数 `@cache`。autouse fixture 每项测试仅切换环境变量，没有清缓存。
- **影响**：后续测试的 debug/日志/导出等调用可能写入首次调用时的测试目录，形成顺序依赖；fixture 宣称的每测试独立数据目录不成立。当前完整测试大部分通过，不能据此证明这种隔离可靠。该问题不意味着本次测试已经写入真实用户配置。
- **建议**：fixture 进入和退出时清理缓存，并确保调用时机在环境变量切换之后；或改成显式可注入/按路径缓存的数据目录服务。增加两个独立测试目录之间的隔离断言。

### A16 RTT 和稳定度缺少“测量已过期”状态

- **位置**：[PingAccumulator.cs](../native/NightreignP2PHelper/PingAccumulator.cs#L20)、[SteamPeerReader.cs](../native/NightreignP2PHelper/SteamPeerReader.cs)。
- **复现**：记录一次 80 ms RTT 后，持续记录 60 秒普通流量、不再提供 STUN RTT 样本；`Snapshot()` 仍返回 80 ms、1 个样本，并报告最新普通流量时间。纯 C# 探针已确认。
- **影响条件**：连接仍有普通流量但测延迟的报文停止时，在线判定可继续通过，而旧 RTT 仍作为当前数值展示。已有多样本时稳定度也基于保留的旧样本，没有独立测量年龄。没有在真实 Steam/ETW 会话验证发生频率。
- **建议**：区分最后流量时间和最后 RTT 样本时间；样本超时后输出未知指标或标明年龄。对显示质量使用同一 freshness 约束，不应因普通数据包持续到达就认为 RTT 新鲜。
- **评论**：该问题无需修复

### A17 预期的持续截图失败会按帧频刷完整堆栈

- **位置**：[capture/plugin.py](../src/nightreign_overlay/plugins/capture/plugin.py#L283)、[log.py](../src/nightreign_overlay/core/log.py)。
- **静态证据**：前台/后台 DLL 模式找不到游戏窗口会抛异常；worker 每次抓取都 `log.exception()` 并关闭后端，下一帧重新尝试。截图周期默认 250 ms，最低 50 ms；日志按天轮换，没有单文件大小限制。
- **影响条件**：使用 DLL 模式、游戏尚未启动且前台门控关闭时，每秒可重复记录多条相同完整异常，浪费磁盘和 I/O，也掩盖其他诊断信息。应用默认前台门控为关闭；重试本身符合项目约定。
- **建议**：保留重试，但对相同预期错误限频或仅在状态变化时输出，恢复时记录一条成功信息；异常堆栈首次输出或放到 DEBUG。必要时对日志增加大小上限。

### A18 血条生产回归仍包含明显的拒识限制

- **位置**：[test_hp_production_videos.py](../tests/plugins/test_hp_production_videos.py)、[hp_assertions.py](../tests/support/hp_assertions.py)、[HP_MATERIAL_DETECTION.md](./HP_MATERIAL_DETECTION.md)。
- **实测结果**：生产视频 yellow_complex 连续回放拒识率分别为 26.28%、27.21%、29.55%（对应 0、0.05、0.25 秒采样）；独立冷启动聚合拒识率 37.84%；个别冷启动连续拒识达到 2.33 秒。pink_complex 冷启动聚合拒识率 21.24%。
- **解释**：按项目现有规则，这些值超过 warning 阈值但没有超过 failure 阈值，因此相关测试通过。本报告没有发现这些测试报告错误输出；**拒识不等于误识**。完整测试的 18 条警告还包含其他算法/历史评估，不能全部当作生产算法的新退化。
- **影响**：实际用户可能经历等待新输出或保留旧标记的时间窗；测试全绿不代表所有场景都及时更新。这是已有能力边界，非本次引入的回归。
- **建议**：发布前明确接受该限制并写入可读用户说明；如目标是更低拒识率，继续改善算法/状态策略并保留现有统计，不能仅放宽阈值消除警告。
- **评论**：该问题无需修复

### A19 热键设置按钮不响应外部绑定变化

### A20 血条文档正文已经被问号替换

### A22 发布 tag 和应用内部版本可以不一致

- **位置**：[__init__.py](../src/nightreign_overlay/__init__.py#L3)、[meta.py](../src/nightreign_overlay/meta.py)、[build-windows.yml](../.github/workflows/build-windows.yml#L68)。

- **影响条件**：发布者忘记修改版本时，ZIP 名、关于页面和诊断归档内的 `app_version` 会互相矛盾。当前 dev 版本本身不是缺陷，也没有证据表明已发布过错误 tag。

## 复核方法与后续验收

以下命令在仓库根目录执行；临时目录只用于隔离检查，不应指向真实用户数据。

```powershell
$env:QT_QPA_PLATFORM = 'offscreen'
$env:PYTHONIOENCODING = 'utf-8'
.venv/Scripts/python.exe -m pytest -q --basetemp .tmp/release-audit-tests -o cache_dir=.tmp/release-audit-cache --durations=15
.venv/Scripts/python.exe -m pytest tests/ui/test_faq.py::test_about_page_contains_screenshot_only_security_statement -q --basetemp .tmp/release-audit-faq -o cache_dir=.tmp/release-audit-cache
.venv/Scripts/python.exe -m ruff check .
.venv/Scripts/python.exe -m ruff format --check .
git diff --check
dotnet build native/NightreignP2PHelper/NightreignP2PHelper.csproj -c Release --no-restore --nologo
```

用于复核边界问题的最小场景：

| 关联问题 | 隔离输入/顺序 | 修复后的期望 |
| --- | --- | --- |
| A04 | YAML 中整数 `.inf`、浮点 `.nan` | 记录 warning 并回退，不出现加载失败/NaN 参数 |
| A05 | 损坏 YAML + 备份重命名失败；保存父路径不是目录 | 不发生未处理异常，保留原文件与未保存状态 |
| A06 | 导入区域 `[0, 0, 1099511627776, 20]`、非正尺寸 | 导入拒绝或重置为未标定，负坐标合法区域仍通过 |
| A07 | 连接失败 + listen 失败 | 不授予主实例资格 |
| A08/A09 | 插件注册服务和订阅后在 on_load 抛错；关闭再启用 | 无残留资源；可恢复或明确提示需要重启 |
| A10 | fake 鼠标启动/pygame 初始化在键盘启动后失败 | 清理所有已创建资源，失败后服务状态一致 |

| A12 | 帧请求→重置设置→旧 generation 帧回调 | 旧回调被忽略 |
| A13 | hat 右→上，不插入中立事件 | 只保留上方向 |
| A14 | fake 系统托盘不可用→关闭主窗口 | 可正常退出或保留明确的可见恢复入口 |
