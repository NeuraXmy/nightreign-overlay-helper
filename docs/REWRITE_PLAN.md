## 3. 插件系统（解决“功能互相依赖”）

### 3.1 插件生命周期

```
discovered ──load()──▶ loaded ──activate()──▶ active
                         ▲                       │
                         └──────deactivate()─────┘
```

- **loaded**：读取 manifest、绑定配置、加载词条。所有已发现插件都会进入此状态，因此即使功能关闭，其设置页 / 教程依然可以浏览与修改。
- **active**：真正开始工作（创建悬浮窗、注册服务、订阅事件、启动定时器）。
- 启用状态持久化在配置 `plugin_manager.enabled.<id>`；用户在页面头部或首页卡片上开关，**无需重启**。

### 3.2 依赖声明与联动

```python
manifest = PluginManifest(
    id="map_detect",
    requires=("capture", "hud"),  # 强依赖：缺失/未启用则本插件无法启用
    optional=("day_timer",),  # 弱依赖：存在则增强功能，不存在也能运行
)
```

- 管理器对 `requires + optional` 做拓扑排序，检测循环依赖与缺失依赖（缺失强依赖的插件标记为 `unavailable` 并在 UI 中提示原因）。
- **启用插件** → 自动先启用其所有强依赖。
- **停用插件** → 自动先停用依赖它的插件（逆拓扑序），并通过 InfoBar 告知用户。
- 弱依赖在运行期可能出现/消失，消费方通过 `ServiceRegistry.serviceChanged` 信号感知。

### 3.3 插件间通信的两种方式

1. **服务契约（请求 / 查询 / 有状态能力）**
   提供方在 `plugins/<id>/api.py` 中定义接口（QObject + 信号 或 Protocol）与数据类，激活时
   `ctx.services.register(DayTimerApi, impl)`；消费方 `ctx.services.get(DayTimerApi)`。
   消费方**只允许 import 提供方的 `api.py`**，不允许 import 其内部实现，从而把耦合面压缩到一个稳定文件。
2. **类型化事件总线（广播事实）**
   以 dataclass 作为事件类型：`ctx.events.publish(GameForegroundChanged(True))`、
   `ctx.events.subscribe(GameForegroundChanged, handler)`。跨线程发布会自动排队到主线程投递。
   插件停用时其订阅自动解除（`PluginContext` 记录订阅并在 deactivate 后清理）。

### 3.4 旧版依赖关系的拆解示例

| 旧版隐式依赖 | 新版处理方式 |
|------------|------------|
| 所有 detector 各自截图、重复转换整帧 | `capture` 基础插件每个检测 tick 只截一帧，发布 `FrameCaptured`；各检测插件订阅后裁剪自己的区域 |
| 缩圈 / 雨中 / 绝招 共用一个悬浮窗 | `hud` 基础插件提供 `HudApi.add_widget(...)`，各功能向同一 HUD 悬浮窗贡献自己的进度条组件，顺序可配置 |
| 地图识别依赖缩圈时间 | `map_detect` 对 `day_timer` 声明 `optional`，通过 `DayStarted` 订阅 Day1 开始/刷新（倒退回第一阶段不触发） |
| 雨中检测与血条检测共享 HLS 颜色配置 | 旧版 `hp_detector` 实际不使用 HLS 颜色，只有雨中检测使用；颜色校准因此归 `rain_timer` 自身（普通 / HDR 两套），不单独设 `hp_color` 插件。`region` 提供通用的冻结屏幕取样 `RegionApi.request_samples(targets)`，后续插件如需取色可复用 |
| 快捷键散落在各处 | `input` 基础插件提供 `HotkeyApi.register(action_id, default_combo, callback)`，统一在其设置页编辑所有快捷键 |
| 检测区域标定 | `region` 服务：`RegionApi.request_region(key)` 统一弹出截图选区窗口，结果存入调用方配置 |

### 3.5 插件分层规划

- **基础插件（infrastructure）**：`capture`（截图引擎 / 检测频率 / HDR 处理）、`input`（全局热键 / 手柄）、`hud`（共享悬浮窗）、`region`（区域标定）。默认启用，首页中归类为“基础功能”。
- **功能插件（feature）**：`day_timer` 缩圈倒计时、`rain_timer` 雨中冒险计时、`map_detect` 地图识别、`hp_marker` 血条比例标记、`art_timer` 绝招倒计时、`p2p_latency` 队友延迟。
- **调试插件**：早期悬浮窗调试插件已移除；悬浮窗底座通过 `tests/ui/test_overlay.py` 和 `tests/platforms/test_overlay_activation.py` 验证，保留调试插件分类供后续诊断工具使用。

### 3.6 设置范围与用户入口

`PluginManifest.settings_scope` 独立于运行时的 `kind` 与依赖关系，决定插件设置在 UI 中的入口：

- `page`：创建独立导航页与首页卡片，适用于用户直接使用的功能插件；这是默认值。
- `general`：不创建导航页或首页卡片，其 `create_settings_widget()` 合并到通用设置页，适用于有少量全局选项的基础能力。
- `hidden`：不创建设置入口、导航页或首页卡片；功能插件在自身页面按需暴露其操作入口，例如“标定区域”或功能自身的快捷键。

用户可见的插件分组顺序固定为 **功能 → 基础 → 调试**。该顺序只影响导航和首页，插件运行时仍按依赖拓扑排序启停。

P2 的范围：`capture` 与 `hud` 使用 `general`；`input` 与 `region` 使用 `hidden`。因此基础服务仍独立加载、启停和提供 API，但不增加用户的页面理解成本。首页的插件卡片与“已启用插件数”也只统计 `settings_scope=page` 的用户可见插件，避免将后台基础服务误认为用户需要管理的功能。

插件的首次启用状态按 `kind` 决定：功能插件与基础插件默认启用，调试插件默认关闭；manifest 可显式覆盖默认值。基础插件由应用托管，始终启用且不接受用户的开关请求，即使遗留配置中记录为关闭也不生效。

### 3.7 悬浮窗拆分策略

插件边界和窗口边界不要求一一对应：业务能力按插件拆分，窗口则按展示职责组合。更新频率、定位规则、交互方式或显示时机差异明显的内容使用独立窗口；视觉形式一致的小型状态信息组合到共享 HUD，避免屏幕上散落多个窗口。

当前使用四个展示容器：

| 窗口 | 内容 | 拆分依据 |
|-----|------|---------|
| `HpMarkerOverlay` | 血量阈值标记 | 动态跟随血条位置、高频更新、固定鼠标穿透，不使用普通的拖动位置持久化 |
| `MapInfoOverlay` | 地图识别结果、水晶布局、识别状态 | 显示区域较大，只在地图识别期间出现，并有独立的切换交互 |
| `HudOverlay` | 缩圈、雨中、绝招等倒计时或紧凑状态 | 视觉形式和更新频率接近，共享位置、缩放、透明度、排列方向与间距 |
| `P2POverlay` | Steam 联机队友、Ping、稳定度 | 保留旧版独立面板、位置与设置；每秒由独立辅助进程更新，不依赖截图和 HUD |

`hud` 是只负责容器和布局的基础插件，不直接依赖或导入任何功能插件。`day_timer`、`rain_timer`、`art_timer` 等功能插件通过稳定的 `HudApi` 注册和移除自己的组件；组件的业务状态及显示内容仍由对应功能插件管理。插件停用时，其 HUD 组件必须随插件上下文自动移除，其他组件和 HUD 窗口继续运行。

依赖关系按以下方式声明：

- `day_timer`、`rain_timer`、`art_timer` 对 `hud` 使用强依赖，需要显示时向 `HudApi` 注册组件。
- `map_detect` 创建并管理独立的 `MapInfoOverlay`，对 `capture` 使用强依赖，对 `day_timer` 使用弱依赖；缩圈阶段只用于优化地图识别时机。
- `hp_marker` 创建并管理独立的 `HpMarkerOverlay`，只依赖截图或血条检测能力，不依赖 HUD 和地图插件。
- `hud`、`map_detect`、`hp_marker` 都通过核心 `OverlayManager` 接入统一的置顶、显示模式和游戏前台可见性管理（规则见 3.9）。

配置归属保持在能力拥有者一侧：`hud` 保存共享窗口的位置、缩放、透明度、排列与间距；倒计时内容和检测参数保存在各自功能插件；地图窗口配置归 `map_detect`；血量阈值、颜色和线宽归 `hp_marker`。这样既能共享窗口基础能力，也不会把功能配置重新耦合到一个巨型 Overlay 插件中。

### 3.8 P2 实施约束

- **实现前先完整审阅旧版，复原优先。** 每项功能须先核对旧版的代码路径、配置项、交互流程、视觉细节和边界行为，再开始重写；不得因局部观察而擅自简化、优化或改变用户已习惯的行为。仅在确认旧版存在明确缺陷、安全风险或平台不兼容时调整，并在实现记录中单独说明差异、理由和影响。
- `capture` 是唯一的周期性截图提供者：功能插件先订阅 `FrameCaptured`，再以自己的插件 ID 调用 `CaptureApi.acquire_stream(owner)` 申请帧流，并在 `PluginContext.on_cleanup()` 中调用 `release_stream(owner)`。首个租约启动定时截图，最后一个租约释放后立即停止；`request_frame(callback)` 用于异步单次请求，回调在 GUI 线程执行。这样没有截图消费者时不会定时抓取屏幕，多个消费者仍共享同一完整帧后各自裁剪区域。
- HDR 图像处理是 `capture` 的统一设置（`plugins.capture.hdr_processing`），不再由各功能插件各自配置。`capture` 不修改共享帧，只在 `FrameCaptured.hdr` 上标记截图时的开关状态；各检测插件按旧版约定自行选择处理方式（如 DAY 模板匹配用 `capture.api.hdr_to_sdr()`，血条/雨中颜色采样保持原图），新的通用转换函数也统一放在 `capture.api`。
- 平台差异与外设能力必须保持可调用的服务契约和可注入测试接口。macOS 使用 mss 主屏截图并保留 Retina 物理像素；“自动”悬浮窗模式优先使用透明悬浮窗，若 macOS 合成器存在显示问题，用户可显式切换普通窗口；Windows 原生 DLL 打包、`pynput` 权限行为和 pygame 手柄实机验证在 Windows 环境执行。
- `capture` 的 mss/Maa 后端创建、截图和关闭全部位于专用 QThread；GUI 线程仅做前台门控、配置快照、流租约和结果发布。帧流只允许一个请求在途，繁忙 tick 直接丢弃；模式切换和停用递增 generation，过期结果不再发布。DAY 标定期间仍暂停该插件的模板匹配；识别前把用户选区缩放到旧版同样的模板标准高度（30 px）。
- 功能插件使用 HUD 时，调用方在自己的 `PluginContext` 中注册清理回调移除组件，保证热停用不会影响其他 HUD 内容。`HudOverlay` 在添加组件后重新激活布局、按最终 size hint 调整窗口并显式展示/置顶，避免初始空容器尺寸导致内容不可见。HUD 提供独立启用开关，关闭时调用窗口隐藏流程而不是将透明度设为零，确保不留下透明顶层窗口。`day_timer` 还原旧版固定 400px、按四段时长比例分配的蓝紫色分段进度条和带阴影白色粗体文字；容器基准尺寸必须包含全部边距，缩放时内容的宽度、进度条高度、文字、圆角和间距同步缩放。HUD 右键菜单仅提供打开主界面与安全退出程序。
- HUD 提供与旧版相同的「隐藏文字」开关（`plugins.hud.hide_text`）：只隐藏各组件的文字标签，进度条保持显示。贡献组件实现可选钩子 `set_hud_text_hidden(hidden)`（与 `set_hud_scale(scale)` 同为鸭子类型约定），添加组件时和开关切换时由 `HudOverlay` 统一调用并重新计算窗口尺寸；雨中/绝招的 HUD 组件已按同一约定接入（见 3.10）。

### 3.9 「仅在游戏时显示和检测」与悬浮窗隐藏优先级

#### 旧版行为（复原依据）

旧版只有一个开关「仅在游戏时显示和检测」（`settings.py` 性能设置组，默认关闭，日志 `Overlay only show when game foreground: ...`），同时作用于：

- **显示**：`overlay`（缩圈/雨中/绝招）、`map_overlay`、`p2p_overlay` 的 `timerEvent` 统一计算 `visible = 自身可见 and opacity > 0.01`，开启时再 `and (is_game_foreground or is_menu_opened or is_setting_opened)`。即自身隐藏原因优先，前台规则只能进一步隐藏；设置窗口打开（`showEvent`/`closeEvent`）或托盘/悬浮窗右键菜单弹出期间视为“正在使用本程序”，悬浮窗保持可见以便调整。
- **检测**：`updater` 中 `if not only_detect or is_game_foreground` 才执行截图检测，**没有**设置窗口/菜单例外。
- **快捷键**：`input.blockSignals(only_detect and not (fg or setting or menu))`，与显示使用相同的例外。
- 地图悬浮窗：地图打开/关闭时将目标透明度设为 1/0 并渐变，透明度 ≤ 0.01 时隐藏；快捷键可手动切换。血量悬浮窗：未检测到血条时隐藏。旧版缺陷：`hp_overlay` 从未接收该开关，不受前台规则约束。

#### 重写版实现

- 开关为核心配置 `app.only_when_game_foreground`（默认 `False`，与旧版一致），位于「通用」设置组，不再属于单个悬浮窗或 `capture`。
- 核心 `ForegroundPolicy`（`core/game_window.py`，由 `OverlayManager` 创建并注册为服务）是唯一的判定来源，开关或前台状态或 UI 活跃状态变化时发出 `changed`：
  - `display_allowed = not enabled or 游戏在前台 or ui_active`
  - `input_allowed = display_allowed`（`input` 插件分发热键前检查）
  - `detection_allowed = not enabled or 游戏在前台`（`capture` 定时截图和 `request_frame()` 检查，无 UI 例外）
  - `ui_active` 由来源集合 `set_ui_active(source, active)` 维护：`main_window`（主界面可见且未最小化）、`tray_menu`、`overlay_menu`（悬浮窗右键菜单）、`region_selection`（区域标定期间）。
- `OverlayWindow.should_be_visible()` 的优先级：**自身请求（`show_overlay`/`hide_overlay`）AND 子类条件 AND 全局前台门控**。子类以 `自身条件 and super().should_be_visible()` 叠加，前台门控只能隐藏，永远不能把一个自身要求隐藏的悬浮窗显示出来。普通窗口模式下豁免前台门控（窗口本身会获得焦点，按前台隐藏会导致无法操作）。
- 任何影响可见性的条件变化后调用 `update_visibility()`；`OverlayManager` 在策略变化时对所有已注册窗口统一刷新。

#### 后续悬浮窗接入约定

| 悬浮窗 | 自身隐藏原因（优先） | 接入方式 |
|-------|------------------|---------|
| `HudOverlay` | HUD 启用开关关闭；无组件 | 已实现：`enabled and super().should_be_visible()` |
| `MapInfoOverlay` | 地图未打开 / 透明度渐变到 0；快捷键手动关闭 | 地图状态和手动切换作为子类条件或 `show_overlay`/`hide_overlay`；渐变结束（≤ 0.01）后才真正隐藏，渐变期间仍受前台门控 |
| `HpMarkerOverlay` | 未检测到血条 | 作为子类条件；修复旧版缺陷，同样受前台门控 |
| `P2POverlay` | 辅助进程未就绪或等待游戏（沿用旧版状态枚举） | 子类状态条件叠加全局显示门控；前台策略不暂停辅助进程或 ETW |

新悬浮窗不得自行读取前台状态或开关，也不得用透明度为 0 代替隐藏；检测插件不需要自行判断前台，`capture` 不产出帧即可。

#### 与旧版的差异

- `hp_marker` 同样受前台规则约束（修复旧版遗漏）。
- 主界面最小化不再视为“设置已打开”（旧版仅在关闭时清除），避免最小化后悬浮窗在后台常驻。
- 普通窗口模式豁免前台门控（重写版新增的显示模式）。
- 区域标定期间视为 UI 活跃，保证标定时悬浮窗和快捷键可用。
- 早期重写版的 `*.overlay.only_when_game_foreground` 与 `plugins.capture.only_when_game_foreground` 键不再读取，不做迁移（未发布版本）。

### 3.10 P3：`rain_timer` 与 `art_timer` 实施记录

#### 共享能力（新增）

- `hud.api.HudTimerBar(color)`：旧版单条倒计时样式（400px 进度条 + 带阴影白色粗体文字），`set_progress(progress, text, color=None)`；`progress <= 0` 时整个组件隐藏，对应旧版 `*_progress_visible`。实现 `set_hud_scale` / `set_hud_text_hidden` 钩子。
- `HudOverlay` 对贡献组件安装事件过滤器，组件自行显示 / 隐藏时重新计算窗口尺寸。
- `RegionApi.request_region(key, label, color)` 支持自定义标注颜色；`RegionApi.request_samples([RegionTarget(id, label, color), ...])` 在同一冻结画面上提供多个标注按钮，返回各框内的冻结像素且不保存区域；无屏幕录制权限（冻结画面不可信）时直接返回 `None`。选区对话框每个按钮各保留最后一个框，旧版“每次框选前需重新点击按钮”的交互保持不变。
- `capture.api` 新增 `crop_rgb(frame, region)`（处理行对齐与越界裁剪）、`resize_to_height(image, height)` 与 `CaptureApi.hdr_enabled()`（供设置页显示当前图像模式）。

#### `rain_timer`

- 复原旧版 `RainDetector`：裁剪血条区域转 HLS，按正常色 / 雨中色（各自 `(亮, 暗)` 两端 ± H/L/S 容差）统计像素占比；雨中占比 ≥ 最大占比且正常占比 ≤ 最小占比判为雨中，反之判为非雨中，其余不改变状态。颜色采样始终用原图（HDR 不做色调映射），普通 / HDR 模式各有内置默认色，校准值替换两端。
- 状态机与旧版一致：识别为雨中且未计时则开始，识别为非雨中且正在计时则停止；倒计时到期只隐藏进度条，不自动停止。文字 `雨中冒险倒计时 m:ss - xx%`，颜色 `#f766ba`。
- 颜色校准：一次冻结画面中提供“正常颜色血条 / 雨中颜色血条”两个按钮（旧版标注颜色），取框内出现次数最多的 HLS，只写入当前图像模式（`plugins.capture.hdr_processing`）的两项；“重置”经确认后只重置当前模式。设置页显示两种颜色的“默认 / 已设置”及色块，HDR 模式带 `HDR:` 前缀。
- 配置：`auto_detect`（关闭后只停止自动识别，手动计时仍可用）、四个校准色；高级选项为持续时间（110 s）、H/L/S 容差（5/30/30）、最小 / 最大面积占比（10%/50%）。
- 日志沿用旧版文案：`In Rain detect enabled`、`Started in rain.` / `Stopped in rain.`、`Started in rain by shortcut/button.`、`Updated hp color: ...`、`align hp color setting canceled`。

#### `art_timer`

- 复原旧版 `ArtDetector`：五个绝招图标（RGBA，缩放到 50px 后取中心一半，alpha 作为掩码），截图区域缩放到 50px，在 0.95–1.05 五个尺度上做带掩码的 `TM_SQDIFF` 并按像素数归一化，最小分数低于阈值（默认 0.02）判为该绝招。HDR 时先 `hdr_to_sdr()`。
- 旧版 `art_info` 原样保留：女爵 / 隐士 / 复仇者延迟 2 s、持续 13 s，学者 20 s，执行者 15 s，及各自颜色与文案；延迟期间进度条保持满格，持续时间结束后清空并隐藏。
- 按下绝招键后等待识别延迟（默认 500 ms）再识别；延迟期间再次按下重新计时，与旧版“记录最后一次按键时间”一致。
- 日志沿用旧版：`Will detect art in ... seconds.`、每种绝招的 `Art type: ..., score: ...`、`Detected art type` / `No art detected`、`detected art: ...`。

#### 与旧版的差异

| 差异 | 理由 | 影响 |
|-----|-----|-----|
| 血条检测区域、绝招图标区域与 DAY I 区域分别由各插件标定（`rain_timer.hp_region`、`art_timer.art_region`） | 插件独立启停，区域归属各自插件 | 旧版配置迁移时需分别映射 |
| 选区按钮统一布局在右侧（旧版绝招按钮在屏幕中央、取消/保存在 0.3 高度） | 选区对话框统一由 `region` 提供 | 仅按钮位置不同 |
| 绝招识别在延迟到期时用 `request_frame()` 异步单次截图，不保持周期帧流；无帧（如前台规则禁止检测）时本次按键直接放弃 | 不需要为偶发识别常驻截图；旧版会挂起等待下一次可检测的 tick | 游戏不在前台时按键不会在回到前台后补识别 |
| 不再保存 `last_art_sc.png` / `art_region_screenshot.jpg` 调试截图 | 调试图写入应用目录，重写版统一用日志诊断 | 排查绝招识别需看日志中的分数 |
| 旧版「启用绝招倒计时」开关由插件启用开关代替 | 插件化后二者等价 | 无 |
| `rain_timer` 设置页新增手动「开始/停止」按钮 | 与 `day_timer` 的手动调整按钮一致，便于无快捷键时操作 | 新增入口，不改变快捷键行为 |
| 识别阈值、延迟、容差、面积占比、持续时间进入「高级选项」 | 第 4 节约定：用户可能调整的参数归入高级选项 | 默认值与旧版相同 |
| 图像缩放用 OpenCV（缩小 `INTER_AREA`、放大 `INTER_LANCZOS4`）代替 PIL `LANCZOS` | 重写版不依赖 PIL | 分数可能有细微差异，阈值保持旧版默认 |
| HUD 高度随组件显隐自适应（旧版固定 400×140） | 多组件共享 HUD 时避免空白区域 | 进度条隐藏时 HUD 收缩 |
| 教程只保留游戏画面类配图 | 旧版设置界面截图与新 UI 不符 | 文字说明改为新 UI 的入口名称 |

## 4. 配置系统

- 声明式配置：插件定义 `ConfigGroup` 子类，类属性使用 `BoolOption / RangeOption / ChoiceOption / Option` 描述默认值与校验规则；实例化后每一项为带 `valueChanged` 信号的 `ConfigItem`。
- 存储：单一用户配置文件 `settings.yaml`（平台用户配置目录），按命名空间分区：`app.*`、`plugin_manager.*`、`plugins.<id>.*`。
- 写入：修改后 500 ms 防抖 + 原子替换写入，退出时强制落盘；非法值回退默认值并记录 warning。
- 迁移旧版 `config.yaml` 时，用户可能需要调整的检测阈值、时间偏移等参数归入功能插件的“高级选项”；仅保留不应由用户修改的内部常量于代码或 `plugins/<id>/tuning.yaml`。
- 设置卡片（`ui/components/setting_cards.py`）直接绑定 `ConfigItem`，双向同步，不依赖 qfluentwidgets 的全局 `qconfig`（其内置卡片会写入 cwd 下的 `config/config.json`）。功能页中的快捷键卡通过 `HotkeyApi` 读取和保存绑定，避免暴露 input 基础插件页面；该 API 的绑定读写能力在 input 的 `on_load()` 即注册，以满足主窗口在插件激活前构造设置页的时序，物理监听仍只在 `on_activate()` 启动。绑定存为 `{device, keys}`，首次读取旧版 `ctrl+shift+d` 字符串时自动迁移；录制使用独立模态窗口，实时展示输入、首个非空输入锁定 keyboard / mousebutton / joystick 设备类型，并提供清空、取消和确认。显示顺序固定为 Ctrl、Alt、Shift、Cmd、普通键；macOS 记录 `pynput` 上报的实际 Ctrl/Cmd 物理键标识，不推断或转换用户的系统修饰键交换设置，以保证录制和运行时匹配一致。

## 5. 多语言（i18n）

- 语言：动态发现，核心 `resources/i18n/<lang>.yaml` 中存在的文件即为支持的语言；当前提供 `zh_CN`（默认/回退）、`zh_TW`、`en_US`、`ja_JP`；“跟随系统”自动选择。
- 新增语言只需在 `resources/i18n` 增加一个完整的 `<lang>.yaml`，无需改代码。文件顶层的 `meta` 段描述语言本身、不参与词条查找：`meta.name` 为语言选择器中显示的本地名称，可选 `meta.locales` 列出额外映射到该语言的系统区域（如 `zh_TW` 声明 `[zh_HK, zh_MO, zh_Hant]`）。语言选择器中回退语言排第一，其余按代码排序。
- 系统区域匹配顺序：精确代码 → 各语言声明的 `meta.locales`（先匹配最具体的形式，如 `zh_Hant_HK` → `zh_Hant`）→ 主语言相同的语言（回退语言优先，如 `zh_SG` → `zh_CN`、`en_GB` → `en_US`）→ `en_US`（若存在）→ `zh_CN`。
- 核心词条必须覆盖每种语言且键与 `zh_CN` 一致；插件和教程只要求提供 `zh_CN`，其他语言文件可选，一旦提供必须完整，且只能使用核心已支持的语言代码。
- **当前阶段仅编写 `zh_CN` 词条。** 其他语言使用回退链显示中文，待后续多语言完善阶段再补充翻译。
- 词条文件为嵌套 YAML，加载后展平为 `a.b.c` 键；`tr("home.title", name=...)` 支持 `str.format` 插值。
- 命名空间：核心词条位于 `resources/i18n`；插件词条位于各自目录，通过 `ctx.tr()` 访问，互不冲突。
- 回退链：当前语言 → `zh_CN` → 键名本身（便于发现漏翻）。
- 教程使用 `tutorial/<lang>.md`，回退链为 当前语言 → `zh_CN` → `en_US`。
- 切换语言后提示重启生效（保持实现简单可靠）。

## 6. UI 设计

- **主界面 `MainWindow(FluentWindow)`**
  - 顶部：首页
  - 中部（可滚动）：仅 `settings_scope=page` 的插件作为导航项，按 功能 / 基础 / 调试 分组
  - 底部：通用设置（包含 `settings_scope=general` 的插件设置）、关于
- **首页**：应用信息横幅（名称 / 版本 / 平台）、运行状态卡片（游戏窗口是否前台、悬浮窗模式、已启用插件数）、`settings_scope=page` 插件的快捷开关列表。
- **插件页**：页头（图标 / 名称 / 描述 / 启用开关 / 依赖状态），下方 `SegmentedWidget` 选项卡：「设置」「教程」，插件可以追加自定义选项卡。
- **通用设置**：语言、主题（浅色 / 深色 / 跟随系统）、主题色、悬浮窗显示模式（自动 / 悬浮窗 / 普通窗口）、仅在游戏时显示和检测、关闭主界面时最小化到托盘、`settings_scope=general` 的插件设置、日志级别、打开配置 / 日志目录。
- **页面级「重置」（重写版新增，旧版无此功能）**：插件页的「设置」选项卡（仅在该选项卡可见，插件无设置内容时不创建）与通用设置页的标题行右侧各有一个「重置」按钮，经确认框确认后把当前页的设置恢复默认，完成后提示“已恢复默认设置”。按钮由 `ui/components/reset_button.create_reset_button(reset, scope, content)` 创建，重置后刷新 `scope` 内不观察配置的快捷键卡片。
  - 插件页调用 `Plugin.reset_settings()`，默认实现为 `ctx.reset_configs()`：重置该插件通过 `ctx.config()` 绑定的全部配置组。由其他插件代存的设置需要插件覆写：`day_timer`、`rain_timer`、`art_timer` 同时把自身快捷键恢复为旧版默认（DAY 三个默认组合键，其余未绑定），并通过 `RegionApi.clear_region(key)` 清除自己标定的区域（region 未激活时跳过）。确认框文案中明确提示快捷键和标定区域会被重置。
  - 通用设置页重置 `AppConfig` 的全部用户选项（跳过内部状态 `tray_hint_shown`，避免再次弹出托盘提示），并依次调用嵌入的 `settings_scope=general` 插件（`capture`、`hud`）的 `reset_settings()`；`hud` 的重置包括悬浮窗位置等窗口配置。
  - 不重置插件启用状态（`plugin_manager.*`），启停仍由页头开关单独管理；语言等需重启生效的选项重置后同样提示重启。
- **标定区域状态与预览（重写版新增，旧版无此功能）**：`day_timer`、`rain_timer`、`art_timer` 的「标定区域」卡片在「标定」按钮左侧显示眼睛图标及带颜色的“已标定”/“未标定”状态（`region.api.RegionStatus`，经 `HotkeySettingCard(accessories=...)` 放入卡片），标定、页面重置或页面再次显示后刷新状态。鼠标悬停时，若已标定，则由 `RegionApi.show_preview(key, color)` 在屏幕上框出该区域，移出或状态部件被隐藏（如切换页面）时 `hide_preview()`；提示文字显示区域坐标与尺寸，未标定时提示“尚未标定区域”。
  - 预览窗口由 `region` 插件持有、全局唯一并复用：无边框、置顶、鼠标穿透、不抢焦点，颜色与该插件选区标注颜色一致；`region` 停用时随上下文销毁。它只在主界面悬停期间出现，不注册到 `OverlayManager`，也不受前台门控影响。
  - 坐标按选区保存约定（`local * dpr + 屏幕偏移`）反算为 Qt 逻辑坐标：取物理范围包含区域左上角的屏幕，找不到时按主屏换算。
  - 状态部件每次刷新或悬停时查找 `RegionApi`，因为设置页可能先于 `region` 激活而构造；服务不可用时按“未标定”显示且不显示预览。
- **托盘**：显示主界面、退出；双击托盘图标打开主界面。
- **悬浮窗基类 `OverlayWindow`**：统一处理无边框 / 透明 / 置顶 / 鼠标穿透 / 不抢焦点 / 拖动 / 位置持久化 / 透明度 / 全局前台门控（见 3.9），以及普通窗口 fallback。

## 10. 风险与应对

- **全屏游戏遮挡悬浮窗**：保持旧版“无边框窗口化”使用建议；周期性重申 TOPMOST。
- **qfluentwidgets 版本变动**：锁定次版本范围（`>=1.11,<1.12`），UI 公共组件封装在 `ui/components`，减少直接散用。
- **插件热启停导致资源泄漏**：`PluginContext` 统一托管订阅、服务注册、悬浮窗与定时器，deactivate 时自动回收。
- **跨线程访问 UI**：检测逻辑在工作线程，结果一律通过信号 / 事件总线回到主线程更新 UI。

整个原生项目（8 个 C# 源文件、csproj、NuGet 锁文件）以及第三方声明和许可证原样复制，逐文件比较与旧版完全一致。没有修改检测算法或修复旧版启发式测量的边界行为：

- 游戏进程检查与 Steam 快照查询均为一秒；自行加载游戏 Steam DLL，保留安装目录与 Steam 库/manifest 回退查找、错误状态和游戏退出清理。
- Steam 候选发现、最近共同游戏 30 分钟窗口、已确认会话记忆、新接口优先/旧接口回退保持不变。
- ETW 保留管理员权限要求、独立实时会话、按远端端点关联、发送 size 56/接收 size 68、前 10 秒覆盖发送时间及之后保留待响应请求的规则；RTT 范围、最后有效 Ping 和取整规则不变。
- 稳定度保留最多 10 个样本、至少 3 个样本、总体标准差及 `1 / (0.01 * jitter + 1)`；新接口仍直接显示 Steam 的本地连接质量。
- 换队过滤保留 3 秒新玩家流量窗口、5 秒旧批次宽限、15 秒不活跃清理。没有增加 PID 过滤、STUN 内容解析、主动发包或 Ping 过期逻辑。
- 主程序服务保留 JSONL 校验、玩家行顺序、完整快照重置重试次数、1/2/4/8/16/30 秒退避、stderr 日志、正常 shutdown 和退出时终止/强制结束兜底。

### 主程序架构适配

- 插件开关代替旧版启用复选框，热停用清理辅助进程和窗口，重新启用新建实例。运行状态通过插件信号更新设置页，窗口订阅服务状态与玩家快照。
- 窗口通过 `OverlayWindow` 注册统一管理，沿用旧版三列 QLabel 布局、昵称提示、缺失指标/旧接口提示、状态文案、灰/绿/黄/红颜色、阈值严格小于比较、310px 基准宽度及缩放截断。默认 75% 透明度（10～100%）、50～200% 缩放、80/150ms 分色阈值与主屏右上重置位置保持不变。
- 接入重写版统一前台规则和普通窗口 fallback。主界面替代旧设置窗口，打开期间允许拖动并显示边框，关闭后锁定；未强制鼠标穿透。新增 `ForegroundPolicy.is_ui_active(source)` 查询指定编辑界面状态，不修改显示或检测门控算法。
- 配置位于 `plugins.p2p_latency` 与其 `overlay` 子节。保留警告阈值至少大于良好阈值 1ms 的约束；局部设置控件读取最终规范值，避免同步信号嵌套导致滑块显示被拒绝的旧值。这是新架构控件适配，不改变原版阈值规则。
- `scripts/build_p2p_helper.ps1` 沿用旧 CI 的锁定恢复、自包含单文件发布和禁止裁剪参数，检查 ETW 支持 DLL 并复制许可；README 说明源码构建和 EXE 同级 `bin` 的发布布局。`.github/workflows/build-windows.yml` 复用完整 `build.bat`，支持手动与版本 tag 触发，将完整 Windows x64 发布目录打包为 ZIP 并上传 Actions artifact。

### 联机悬浮窗风格与通用设置调整

按用户要求，联机悬浮窗改为无面板背景、无标题，所有状态与玩家文字使用与 HUD 相同的黑色阴影（blur 10、alpha 150、offset 0）。未连接游戏/Steam 或出现辅助程序错误时显示原始状态；正常运行显示玩家三列列表，无队友时显示等待提示。缺失指标仍显示 `--`，接口与延迟来源保留昵称 tooltip，不再显示单独的旧接口提示行。普通窗口 fallback 仍沿用共享基类的不透明背景。

设置页复用 `OverlaySettingSection`，包含缩放、透明度、普通/锁定/鼠标穿透和位置重置/水平重置；移除主界面打开期间才允许拖动的旧版限制，采用与 HUD 相同的输入模式。全局前台规则、主界面/菜单/选区临时显示例外及普通窗口模式例外均来自共享基类。Steam/ETW 仍独立运行，不受截图检测暂停规则影响，并在设置页和教程中明确说明；没有修改原生检测算法。

修复动态标签尚未参与布局时测量高度导致文字挤压/缩成横线的问题，测量前显示并 polish 新标签、立即隐藏待删除标签、计入面板边距并应用布局。新增连续 64 快照回归、状态/阴影/无标题检查、穿透切换和两个重置按钮检查。


### 地图绘制内容 i18n 机制

中文 `data/csv/names.csv` 原样迁移到 `i18n/zh_CN-names.csv`（逐字节确认一致），其他语言使用 `i18n/<语言代码>-names.csv`；按 ID 合并，缺失文件、条目或空名称回退中文。名字表只影响显示，不修改地图模板、建筑/位置数据、匹配评分或候选顺序。检测器接收插件上下文的启动语言，独立调用时使用应用语言；未提供其他语言翻译。

地图绘制中的首领/额外首领、楼顶/地下室、血瓶、楼层、庇佑、隐藏夜王、缩圈位置和事件文案，以及水晶图例、已接入的识别中/候选/水晶布局提示和新增的时间单位均通过插件 YAML 词条加载，缺失词条回退中文。资源格式与新增语言方式见 `map_detect/i18n/README.md`。

地图生命周期、完整旧版检测与绘制逐像素对照、核心 i18n 和新增名字表/词条回退测试合计 **69 项通过**。保留地图 POI 评分旧/新版一致的两条已知警告；Ruff 与 diff 检查通过。没有测试真实游戏或非中文人工布局；其他语言的名称长度/字体覆盖需在加入翻译后检查。


### 悬浮窗重置位置持久化

通用悬浮窗的「重置」与「仅水平重置」通过当前窗口计算默认位置，并立即把实际坐标写入配置；不再依赖重置后的拖动来保存具体坐标。水平重置保留当前纵坐标。网络状态悬浮窗仅保留「重置」按钮，移除水平重置，并同步更新教程。回归测试覆盖窗口显示/隐藏时点击重置后不拖动、重新加载配置并重建窗口的位置，以及网络状态页仅显示一个重置按钮。

主悬浮窗以顶部中心为锚点，网络状态悬浮窗以右上角为锚点。缩放与内容宽度变化时调整左上角横坐标并持久保存，保持锚点不变；同时记录保存时的宽度，以便重启后窗口从初始尺寸逐步加载内容时仍恢复同一锚点。旧配置没有宽度记录时按原坐标兼容恢复。

地图候选切换、水晶布局切换和重新识别五个快捷键增加地图信息悬浮窗可见性门控：同时检查显示意图和 Qt 实际可见状态，隐藏动作开始渐隐时立即禁用。重新识别使用独立快捷键入口，保留 Day1、区域变化和定时间隔等自动识别流程。
