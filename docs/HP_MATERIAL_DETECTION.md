# 血条材质分割与端点检测

更新：2026-10-17。当前实现已接入主程序。四段源录像在全帧、50 ms、250 ms 请求间隔下均零误报，连续回放拒识率均低于 20%。复杂背景两项准确性测试已移除严格 xfail，按正常测试验收。

## 本次改动的依据

目标是可用容量终点 U：包含彩色血量与空血，排除扣上限灰段。原始外框终点 T 可能在 U 右边。空血会透过游戏背景，因此“暗、均匀、下缘高光弱”不能定义空血；增加端点投票次数也不能把持续出现的背景边缘变成 HUD。

本次改为相对外观的材质分类，结合有序分割、端点验证和外框结构约束。不同录像使用同一组模型和规则。运行时不接收 GT、录像编号、帧号、恒定血量标签或固定长度比例。

## 实现与生命周期

- `material_features.py`：纵向归一化到 24 行，保留原始横向像素。相对左侧彩色填充和条外上下文计算 72 维亮度、色度与通道差特征。横坐标不作为特征。
- `material.py / MaterialModel`：两个小型随机森林，分别输出可用槽体／灰段／背景概率和局部端帽概率。端帽模型查看左右局部邻域，共 360 维，不接收候选横坐标。模型以 ONNX 随程序打包，复用已有 `onnxruntime`，应用无需 scikit-learn。
- 有序分割最大化“可用槽体 → 可选灰段 → 背景”的联合似然。用前缀和与后缀最大值在线性时间内求 U、T，允许无灰段时 U=T。模型提供边界语义，局部亮脊及端帽分类校正具体像素位置。
- 外框之后应不再延续填充截面或暗槽。以真实条外行作参照检查该条件，避免将复杂背景中的受伤内边界当成外框。
- `MaterialHpDetector`：最近五次调用中至少三次坐标一致才输出，当前调用必须提供有效证据。缺失观测占用窗口；无效截面清空确认。不会将旧长度当成新观测，增长和缩短采用相同规则。只保留少量坐标，不保留视频帧。
- 模型会话由检测器持有，重置历史时复用会话；停用或切换算法时随对象释放。没有全局模型单例。离线评估可显式共享无状态模型，但各个检测器的历史独立。
- `tracking.py`：完整纵向结构成立后使用材质路径；证据丢失则拒识，防止扫描线重新获取灰段外端点。没有完整截面的旧窄裁剪保留扫描线兼容路径。

## 标定与实际截图

用户仍按旧版标定：**左边缘紧贴血条起点，高度与血条一致，宽度不限**。无需手工扩大框选。新版实际截图向上下各补一倍原高度，向右扩展默认 125 倍原高度；与所在显示器物理范围、当前截图帧范围同时相交。负坐标副屏、混合 DPI 和客户区截图均保留原有物理坐标约定，不采集相邻屏幕或空隙。

后台任务同时传入原标定中线和高度。归一化根据标定高度进行，不把黄血实际有色行带较薄误认为 HUD 整体缩小。不对称截断也不会改变原始取样中线；缺少完整截面时可以拒识。归一化边界的反射补齐仅发生在已取得的数组内部，不扩大屏幕采集范围。

检测结果始终相对截图左侧；覆盖标记的位置、高度继续由原标定框决定。旧离线裁剪包含左侧留白时，可按可见左端帽归一化，返回坐标时还原该偏移；生产截图不移动用户的左侧锚点。

## 四段源录像验收

使用 `production_annotations.json` 的人工端点和稳定区间，容差 ±3 px。两段灰血录像的过渡区间不评分，但仍向检测器供帧；粉血和黄血整段评分。每个采样间隔从源第零帧独立启动，不在 GT 段边界重排采样相位。250 ms 请求实际每八帧取样，约 266.7 ms。

| --- | ---: | ---: | ---: | ---: | ---: |
| hp_1.mp4 | 3.72% | 3.60% | 0% | 0 / 111 | 0 s |
| hp_2.mp4 | 0% | 0% | 0% | 0 / 94 | 0 s |
| 2026-10-16 20-19-02.mp4（粉血） | 12.43% | 12.09% | 8.70% | 0 / 230 | 1.60 s |
| hp_3.mp4（黄血） | 17.09% | 17.38% | 18.18% | 0 / 176 | 1.60 s |

三种频率的全部有效输出均在容差内。四段原 MP4 与无损 fixture 的所有预测范围、错误明细、拒识计数、拒识时长和冷启动结果完全一致，仅实际处理耗时不作相等要求。完整快照见 [production_report.json](../tests/data/hp_detect/videos/production_report.json)。

在每个稳定段内每秒重新启动，分别独立运行五秒，共 21+16+57+42=136 个窗口。全部零错误、全部能输出；最慢首次输出分别为 1.60、0.53、1.60、2.13 秒。灰血两段最坏窗口拒识分别 36.84%、10.53%；粉血、黄血分别 63.16%、57.89%，**不是每个五秒窗口都低于 20% 或 50%**。四段冷启动合计拒识率分别 15.79%、10.53%、21.70%、27.94%，统计包括三次确认的启动开销。

单次处理平均约 3–7 ms、P95 约 4–8 ms，依输入宽度和负载变化；不含视频解码，也不含首次加载模型会话的开销。

## 训练、留出验证与适用边界

打包模型使用四段录像中每八帧抽样的稳定标注段训练，包含底部两行上下文缺失的反射增强。每类材质至多抽取一万个像素列；端帽标签为人工 U、T 附近的局部外观，其他位置为负例。模型只学习局部外观，非半血分界和固定输入尺寸下的外框双向变化另有合成测试。数据与随机种子见 `data/training.json`，离线训练入口见 [tools/hp_material](../tools/hp_material/README.md)。

**上表是参与训练／优化录像的回归成绩，不能作为独立泛化准确率。** 另训练一个排除交替五秒时间块的模型，仅对未参与训练的块评分：250 ms 下四段均零误报，拒识率 4.26%、19.64%、10.81%、16.05%；逐帧仍有灰血 8 次、粉血 1 次错误，50 ms 灰血 1 次错误。这表明罕见特效与背景仍可能造成误判，尚不能保证新录像、HDR、其他 HUD 比例或完全没有有色前缀时的效果。详细留出记录见 [heldout_block_report.json](../tests/data/hp_detect/videos/heldout_block_report.json)。时间块留出也不等于整段新录像留出。

旧 `hp_footage_*.mkv` 裁剪缺少实际生产所需的部分上下文，继续保留连续回放与静态兼容测试，但冷启动验收已迁移到同源、全时长、实际截图范围的 production fixture，保留灰血窗口的零错误、拒识低于 50%、两秒内首次输出标准。直接向当前模型输入旧窄裁剪，第一段最坏五秒窗口拒识 52.63%、最慢首次输出 2.40 秒；该差异不能隐去或当作生产截图结果。

下一步需要新的独立源录像，尤其是带灰段且场景／特效更复杂的素材。应保留录像级隔离和误报明细，避免用继续增加固定比例、固定端点或更长锁定时间掩盖泛化问题。

## 复现与回归

```powershell
$env:QT_QPA_PLATFORM='offscreen'
python -m pytest tests/plugins/test_hp_material.py tests/plugins/test_hp_complex_scenes.py tests/plugins/test_hp_production_videos.py tests/plugins/test_hp_marker.py -q
python -m tests.support.hp_production_evaluation --output .tmp/production_report.json
python -m tests.support.hp_production_evaluation --source-dir sandbox --output .tmp/source_report.json
```

回归还覆盖非半血 U、输入尺寸不变时 T 双向改变、HUD 消失、输入不变性、材质失败不回退灰段外沿、实际异步工作线程到覆盖标记、上下边缘裁剪与多屏坐标。最终血条专项 260 passed，Ruff 检查／格式检查及差异空白检查通过。全仓库复测为 733 passed、3 failed；三项失败均为地图插件 en_US／ja_JP／zh_TW 翻译缺键。
